# Fresh Pick 제품/설계 노트

## 제품 방향

Fresh Pick은 마트 진열대 앞에서 사용자가 여러 신선식품 후보를 사진으로 비교하고, 지금 장바구니에 넣을 후보를 빠르게 고르도록 돕는 장보기 보조 앱이다.

핵심 약속은 공식 등급이나 식품 안전 판정이 아니라 다음 질문에 답하는 것이다.

> 지금 눈앞에 있는 후보 중 어느 상품이 사진상 더 좋아 보이는가?

## 지원 카테고리

현재 웹 MVP는 세 가지 모드로 동작한다.

- 소고기 구이용: 색 안정감, 지방 분포, 표면/포장 반사, 구이용 적합도
- 잎채소: 초록색 선명도, 생기, 시든 부분, 변색/상처 신호
- 토마토: 붉은 색 균일도, 표면 안정감, 눌림/상처/무름 의심 신호

이후 확장 후보:

- 과일: 사과, 바나나, 딸기, 포도
- 추가 채소: 오이, 파프리카, 양파, 감자
- 추가 육류: 삼겹살, 목살, 닭고기

## 사용자 흐름

1. 사용자가 상품 종류를 선택한다.
2. 후보 사진 2-5장을 업로드한다.
3. 앱이 상품 영역을 자동 지정한다.
4. 사용자가 상품 영역을 확인하거나 수정한다.
5. 가격표가 있으면 라벨 영역을 지정해 OCR을 실행한다.
6. 가격표가 없으면 `가격표 없음`을 선택한다.
7. 앱이 사진, 상품 영역, 구매 정보를 바탕으로 후보를 비교한다.
8. 결과 화면에서 BEST PICK, 가성비 후보, 후보 간 차이, 주의 신호를 확인한다.
9. 최근 분석은 원본 이미지 없이 작은 썸네일과 텍스트 중심으로 브라우저에 저장된다.

## 분석 설계

분석은 두 층으로 구성한다.

- 라이브 분석: 멀티모달 LLM에 상품 영역으로 잘라낸 이미지를 전달해 카테고리별 기준으로 비교한다.
- 로컬 fallback: API 실패나 한도 초과 시, 이미지 픽셀 단서 기반 휴리스틱으로 임시 비교 결과를 제공한다.

공통 분석 필드:

- 핵심 상태 신호: 고기에서는 지방량, 잎채소에서는 생기, 토마토에서는 색/숙도
- 분포/균일도 신호: 고기에서는 지방 분포, 야채에서는 색/형태 균일도
- 색상 신호
- 표면/사진 품질 신호
- 종합 판단

## 비용/보안 원칙

- API key는 서버 로컬 파일 또는 환경변수에서만 읽는다.
- 브라우저에는 API key를 절대 전달하지 않는다.
- 하루 분석 횟수와 OCR 횟수를 제한한다.
- 한 번의 실제 LLM 분석에 전달하는 이미지는 기본 3장으로 제한한다.
- 사용량 예약을 서버 프로세스 안에서 직렬화해 동시 요청으로 제한이 새는 일을 줄인다.

## UX 원칙

- 첫 화면은 장보기 앱보다 신선식품 스캐너처럼 보여야 한다.
- 고기만 떠올리는 검붉은 톤보다, 야채 확장을 고려한 그린/민트 기반 팔레트를 사용한다.
- 결과는 점수보다 `왜 이 후보인지`를 먼저 보여준다.
- 모든 판정 문구는 사진 기준 참고 표현을 사용한다.
- 안전, 신선도 보증, 공식 등급 확정처럼 오해될 수 있는 표현은 금지한다.

## 다음 고도화 우선순위

1. 더 많은 카테고리 프리셋 추가
2. 상품 영역 자동 탐지 정확도 개선
3. 라벨 OCR 결과의 날짜/가격 신뢰도 표시 강화
4. 동일 카테고리 샘플 이미지 기반 회귀 테스트 세트 구축
5. 사용자 취향 기억 기능
6. 모바일 촬영 흐름 최적화

## 최근 반영

- 상품 종류별 판별 기준 칩을 추가해 현재 모드에서 어떤 신호를 보는지 즉시 확인할 수 있게 했다.
- 라벨 OCR 결과에 신뢰도, 반영된 항목, 주의 문구를 별도 패널로 표시한다.
- 포장일과 소비기한/표시일 입력란을 후보 카드에 노출해 OCR 결과를 사용자가 직접 검수할 수 있게 했다.
- 마지막 상품 종류와 카테고리별 취향 기준을 브라우저에 저장해 반복 사용 시 시작 지점을 줄였다.
